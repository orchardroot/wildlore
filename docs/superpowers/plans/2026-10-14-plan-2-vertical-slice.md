# Plan 2: Vertical Slice (Macclesfield to Buxton) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A playable v0.1.0: title screen, new game in Macclesfield, choose a starter from Professor Garside, beat rival Kit, walk Macclesfield Forest and the Cat and Fiddle road to Buxton, catch wild creatures in British weather, heal at a Sanctuary, shop at a Corner Shop, and beat Keeper Maud at the Buxton spa for the first Stone. HD-2D presentation, 20 creatures with generated pixel art, save and continue, Mac and Windows builds.

**Architecture:** Plan 1's pure-logic core (`battle/`, `data_api/`, `core/`) stays untouched apart from small additions. On top of it: autoload singletons hold game state and route between scenes; zones are JSON grids that `ZoneBuilder` turns into low-poly 3D at load time; characters and creatures are pixel-art `Sprite3D` billboards generated by a headless GDScript sprite tool from JSON recipes; the battle scene plays back `Battle` events; NPCs and story run on a tiny command-list script interpreter. Every visual task verifies itself with an in-game screenshot hook (`--shot`), and a headless playtest bot plays the slice end to end in CI.

**Tech Stack:** Godot 4.7.2 GDScript, Compatibility renderer (OpenGL 3.3, verified on the GTX 775M: shadows and glow work), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-14-wildlore-design.md` (M1 in section 9). Plan 1: `docs/superpowers/plans/2026-10-14-plan-1-foundations-and-battle-core.md`.

**Plan style note:** Plan 1 was pure logic, so every line of code was in the plan. Much of plan 2 is scenes, art and content where the right answer is found by looking at a screenshot. Tasks therefore pin down every shared contract exactly (file paths, class names, signatures, data formats, event names) and give tests for all logic, but leave scene layout and art recipes to the implementer, with a screenshot acceptance check. Shared contracts are owned by Tasks 1 to 3 and must not be changed by later tasks without a ledger ruling.

## Global Constraints

- Everything from plan 1's Global Constraints still applies (tabs, int casting from JSON, British spelling, no em-dashes, Co-Authored-By trailer, `tools/test.sh` must stay green, push after every commit).
- Work happens on branch `plan-2-slice` (parallel agents use their own worktree branches `p2-<task>` and the controller merges them into `plan-2-slice`). PR to `main` at the end, tag `v0.1.0`.
- Do not modify `battle/*.gd` or `data_api/*.gd` except where a task explicitly says so.
- Never add autoloads other than the five in Task 1. Never edit `project.godot` input map except in Task 1.
- 1 world unit = 1 tile. Sprite pixel size `1.0 / 32.0` (a 32 px wide sprite is one tile wide).
- All new art is generated by `tools/spritegen.gd` from recipes in `art/recipes/`; generated PNGs are committed under `art/sprites/`. No downloaded art.
- All audio is generated by `tools/sfxgen.gd` into `audio/`; no downloaded audio.
- Every scene-producing task must produce at least one screenshot via the `--shot` hook into `docs/screens/<task>-<name>.png`, commit it, and look at it (read the PNG) before claiming done.
- Medium quality preset must hold 60 fps on the iMac: keep draw calls down (MultiMesh for repeated tiles and props), shadows on the sun only.
- Text is written for age 11 and up: witty, warm, never grim; no swearing.

## Review Focus

1. **Soft-locks in the overworld.** Player can never end up inside a non-walkable tile, behind a one-way blocker with no exit, or in a zone with no route back. Pinned by the zone validator (warp targets exist, arrival tiles walkable, every warp has a reachable return) in Task 2 and by the playtest bot in Task 12.
2. **Losing a battle.** Whiteout must heal the party and return the player to the last Sanctuary (or Macclesfield if none), deduct some money, and never re-trigger the same trainer battle forever. Pinned by `test_whiteout_returns_to_sanctuary` (Task 8) and the bot's hostile run (Task 12).
3. **Save and continue mid-journey.** A save made anywhere (zone, position, party with statuses, bag, flags, clock) loads back identically; a save from an older format migrates. Pinned by `test_game_state_round_trip` (Task 1).
4. **Battle flow edge cases in the UI.** The player's creature faints with reserves (must pick a replacement, cannot cancel), the last creature faints, catching with a full party (goes to the Ark), learning a fifth move (replace or skip), evolving after battle. Pinned by battle scene tests driven by scripted actions (Task 5).
5. **Missing assets.** A creature without a sprite shows the `?` placeholder; a zone referencing an unknown tile char fails validation rather than rendering holes. Pinned in Tasks 2 and 4.

**Zone JSON (binding):**

```json
{
  "id": "macclesfield",
  "name": "Macclesfield",
  "region": "cheshire",
  "kind": "town",                       // town | route | interior | dungeon
  "music": "town_cheshire",
  "weather": {"drizzle": 50, "clear": 30, "fog": 10, "sunshine": 10},   // interiors: {}
  "ground_height": 0,
  "rows": [                              // y = row index, x = column; all rows same length
    "TTTTTTTTTT",
    "T..,,,..#T"
  ],
  "heights": ["0000011111", "..."],      // optional, same shape, digit = level (0..9); 1 level = 0.5 units
  "legend_extra": {"A": {"tile": "grass", "prop": "oak"}},   // optional per-zone chars
  "props": [{"type": "building", "style": "red_brick", "x": 3, "y": 2, "w": 4, "h": 3, "door": [5, 4], "label": "Sanctuary"}],
  "warps": [{"x": 5, "y": 4, "to": "macc_sanctuary", "tx": 4, "ty": 7, "facing": "up"}],
  "edges": {"north": {"to": "macc_forest", "offset": 0}},   // walking off this edge enters that zone
  "npcs": [{"id": "garside", "sprite": "prof_garside", "x": 6, "y": 3, "facing": "down", "script": "garside_intro", "move": "still"}],
  "encounters": {"grass": [{"species": "scuttlet", "min": 2, "max": 4, "weight": 40, "time": ["day", "dusk"], "weather": []}], "water": []},
  "signs": [{"x": 2, "y": 2, "text": "MACCLESFIELD. Silk town. Mind the hills."}],
  "spawn": [4, 6]
}
```

Base tile legend (binding; `legend_extra` may add more):

| Char | Tile | Walkable | Notes |
|---|---|---|---|
| `.` | grass | yes | |
| `,` | tall_grass | yes | wild encounters (`encounters.grass`) |
| `#` | path | yes | gravel/flagstone |
| `=` | road | yes | tarmac with kerb edges |
| `:` | cobbles | yes | |
| `s` | sand | yes | |
| `f` | flowers | yes | decorative |
| `~` | water | no | `encounters.water` later (surf) |
| `w` | shallow | yes | brook you can wade, splash fx |
| `T` | tree_oak | no | |
| `P` | tree_pine | no | |

| `W` | drystone_wall | no | |
| `F` | fence | no | |
| `R` | rock | no | gritstone boulder |
| `^` | cliff | no | auto-generated where height drops by 2+ levels |
| `B` | building_block | no | under building props (validator checks props cover them) |
| `x` | void | no | nothing rendered (interiors outside the room) |
| `|` | floor_wood | yes | interiors |
| `+` | floor_tile | yes | interiors |
| `C` | counter | no | interiors (talk across it) |
| `L` | ledge_south | one-way | jump down southwards only |

`ZoneData` (class_name ZoneData): `static from_dict(d) -> ZoneData`, fields mirror the JSON (`width`, `height`, `tiles: Array[Array[String]]` of tile names, `heights: Array[Array[int]]`, `props`, `warps`, `edges`, `npcs`, `encounters`, `weather`, `signs`, `spawn: Vector2i`), `tile_at(p: Vector2i) -> String`, `walkable(p: Vector2i, from_dir := Vector2i.ZERO) -> bool` (out of bounds false; ledges walkable only moving south; NPC occupancy is handled by the overworld, not here; height difference > 1 level between neighbours is not walkable), `warp_at(p) -> Dictionary`, `validate(all_zone_ids: Array) -> Array` (errors: ragged rows, unknown chars, heights shape mismatch, warp/edge targets missing, warp arrival tile not walkable in the target zone, spawn not walkable, sign/npc on unwalkable tile, building props overlapping `B` mismatch).

`ZoneBuilder` (class_name ZoneBuilder, a RefCounted): `static func build(zone: ZoneData) -> Node3D` returning a node tree: ground (one MeshInstance3D per tile type, built with SurfaceTool as merged quads with per-vertex colour variation for a hand-painted look), walls and hedges (merged meshes), trees and rocks (`MultiMeshInstance3D` per prop type using `Meshes` shapes), water (one mesh with `art/shaders/water.gdshader`), buildings (box body with plaster/brick/stone colours, pitched roof prism with slate or tile colour, door, windows as emissive quads that glow at night, chimney), height levels as stepped blocks with cliff faces. Deterministic: a per-zone seed from the id hash drives all variation.

`Meshes` (class_name Meshes): static constructors returning `ArrayMesh`: `oak()`, `pine()`, `birch()`, `bush()`, `rock()`, `hedge_segment()`, `wall_segment()`, `fence_segment()`, `flower_patch()`, `tall_grass_tuft()`, `building(w, h, style) -> ArrayMesh`, `lamp_post()`, `bench()`, `sign_post()`. Low-poly, flat-shaded, vertex-coloured (no textures), each under 300 triangles.

### Task 4: Sprite generator and the 20 creatures' art (subagent, Sonnet, worktree)

**Files:** `tools/spritegen.gd` (+ `tools/spritegen/*.gd` helpers), `art/recipes/creatures/<id>.json`, `art/recipes/chars/<id>.json`, generated `art/sprites/creatures/<id>_front.png`, `<id>_back.png`, `<id>_icon.png`, `art/sprites/chars/<id>.png`, `art/sprites/creatures/_placeholder_*.png`, `art/sprites/chars/_placeholder.png`, tests `tests/art/test_spritegen.gd`, contact sheet `docs/screens/t4-creatures.png`.

**Contract:**
- Run: `godot --headless --path . -s res://tools/spritegen.gd -- [id ...]` (no ids = all recipes). Deterministic output.
- Creature sprites: front and back are 192x96 PNGs = two 96x96 idle frames side by side (frame 2 is a 1-2 px breathing/bob variation). Icon is 32x32. Character sheets are 96x192 (3x4 frames of 32x48).
- Recipe format (creature): `{"id", "palette": {"name": "#rrggbb", ...}, "layers": [{"shape": "ellipse"|"circle"|"rect"|"poly"|"line"|"tri", "at": [x, y], "size"/"points"/"r": ..., "colour": "<palette name>", "shade": true|false, "pattern": "none"|"speckle"|"stripes"|"spines"}], "back_layers": [...] (optional; default mirrors with a darkened palette and no face), "eyes": [{"at": [x, y], "r": 4, "colour": ...}], "outline": "#hex"}` in a 96x96 canvas. The renderer draws layers in order, applies light-from-top-left shading with 3 tones per colour (base, shadow, highlight) and an ordered dither on transitions, then a 1 px dark outline around the silhouette, then eyes with a highlight pixel. Character recipe: body template (`"build": "child"|"adult"|"elder"`), palette for skin, hair, top, bottom, shoes, accessory (`hat`, `glasses`, `labcoat`, `scarf`, `backpack`), and the generator draws the 12 walk frames.
- Recipes for all 20 creatures of this slice (the nine starters and the eleven from Task 10's list) and characters: `player_a`, `player_b` (the player picks one at New Game), `prof_garside` (elder, labcoat, grey bun), `kit` (rival, child, red hoodie, phone), `keeper_maud` (adult, swimming cap and towel cape, Buxton spa keeper), `mum`, `villager_1..6` (palette variety), `sanctuary_nurse`, `shopkeeper`, `hiker`, `birdwatcher`, `angler`, `jogger`, `warden_grunt` (Enclosure Warden, olive gilet with shepherd's-crook badge).
- Each creature must read clearly as its animal at 96 px: silhouette first. Use the reference list below. Iterate: render, read the PNG, fix, until each one looks like a confident Switch-era pixel sprite rather than a blob.
- `tests/art/test_spritegen.gd`: rendering a tiny recipe yields the right size, an outline pixel exists at the silhouette edge, transparent background, determinism (same bytes twice).
- Placeholder sprites: a friendly `?` in a dashed circle.
